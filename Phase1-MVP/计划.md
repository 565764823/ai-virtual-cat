## 三、技术方案与关键决策

### 3.1 核心链路

```
启动 → 迁移建库（user_version）→ 建游客存档 → 判档
  ├─ 无猫 → 选猫界面 → 选猫 + 命名 → 领养落库(cats.is_adopted=1)
  └─ 有猫 → 主界面（聊天 / 提醒 / 心情 tab）
聊天：用户输入 → 人设 Prompt(按猫渲染) → 本地 LLM 流式 → 落库 messages
提醒：reminders 表 → 定时触发 → 桌面通知 + 游戏内通知 → 一键打卡
心情：每日打卡 → mood_records → XCharts 曲线
```

### 3.2 关键决策点

- **完整技术栈依赖**：sqlite-net-pcl（NuGetForUnity 装，带 SQLitePCLRaw）+ UniTask（git URL）+ VContainer（git URL）+ XCharts（git URL），对齐技术栈冻结选型。
- **DDL 归迁移 SQL，sqlite-net 只做 CRUD 映射**：绝不用 `CreateTable<T>()`（会生成 PascalCase 列名 + 缺 CHECK/索引）；表结构由 `0001_init.sql` 原始 SQL 建出，模型用 `[Column("snake_case")]` 映射。
- **时间戳一律 `string`（YYYY-MM-DD HH:MM:SS）+ `storeDateTimeAsTicks:false`**：对齐 schema.sql 的 TEXT 约定，避免 DateTime 被存成 ticks。
- **程序化 uGUI + Screen 框架**：延续 T0-6「避免 .unity 二进制场景入库」，引入 UiBuilder/ScreenManager 管理多界面切换。
- **选猫数据用代码常量**（`ICatCatalog` + `CatCatalog` 实现），非 ScriptableObject，未来可换 SO 实现。

### 3.3 数据/模块（本阶段新增或改动）

- 新增目录 `Phase1-MVP/`（本阶段流程文档与交付物）
- 改 `Phase0-筹备/scaffold/`：新增 `Assets/Scripts/Data/`（Models + Repositories + Migration + Serialization）、`Core/`（DI + Services + SessionState）、`UI/`（UiBuilder + ScreenBase + ScreenManager + Screens）；`ChatBootstrap.cs` 替换为 `AppBootstrap.cs` 入口
- 启用数据表：`users`/`cats`/`conversations`/`messages`/`reminders`/`mood_records`（MVP 读写）；`memories`/`emotion_logs` 等建表但 P2 启用
- 依赖：manifest.json 加 3 个 git URL 包 + NuGetForUnity 装 sqlite-net-pcl + asmdef 加程序集引用

## 四、开发顺序与里程碑节点

1. **地基**：T1-0 依赖 + 数据层 → T1-1 游客存档 → T1-2 选猫领养（第一个 task-complete，验收「首启选猫→领养→重启直进主界面」）
2. **核心对话**：T1-3 文字聊天扩展（短期上下文 + UniTask 流式）
3. **记录与提醒**：T1-5 心情记录 + T1-4 基础提醒（可并行）
4. **收尾**：T1-6 猫咪状态 + T1-7 基础安全 + T1-8 埋点
5. **M1 验收点**：MVP 内测版本，核心闭环（选猫→聊天→提醒→记录）可用

## 五、验收标准（Definition of Done）

- [ ] 首次启动进入选猫界面，展示 ≥3 只可选猫（品种/性格/外观）
- [ ] 用户可完成「选猫 → 命名 → 领养」，领养结果持久化到 cat.db（cats.is_adopted=1）
- [ ] 再次启动直接进入已领养猫咪的主界面（游客存档）
- [ ] 输入文字后本地 LLM 流式返回猫咪口吻回复，单轮上下文连贯
- [ ] 可创建一次性/循环提醒，到期触发桌面 + 游戏内通知，提醒后可一键打卡
- [ ] 可完成每日心情打卡并持久化，展示简单曲线
- [ ] 猫咪三态（心情/精力/健康）值展示与简化增减
- [ ] 敏感词过滤生效，不误杀正常对话
- [ ] 核心行为埋点落库
- [ ] 数据层迁移器对齐 schema.sql（user_version + schema_migrations，幂等 + 损坏自恢复）

> 每一条都要「可验证」，对应 [`合并代码.md`](合并代码.md) 的测试用例。
> **跨功能一致性**：选猫→聊天→提醒→记录涉及「数据层 ↔ AI 引擎 ↔ UI」多模块衔接，验收时补「端到端联调」项。

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| sqlite-net-pcl 原生库（SQLitePCLRaw）在 Unity 链接坑 | bundle_green 桌面端成熟；兜底 Microsoft.Data.Sqlite（技术选型确认 §3.5） |
| 误用 CreateTable<T> 破坏 schema | 铁律：DDL 只来自迁移 SQL，模型仅 [Column] 映射 |
| DateTime 存成 ticks 破坏 TEXT 约定 | 全 string 时间戳 + storeDateTimeAsTicks:false |
| Unity 拉 git URL 包需联网（本机代理） | 用户本地 Unity 验证编译；UniTask 有 gitee 镜像兜底 |
| VContainer 注入动态 AddComponent 的 MonoBehaviour 依赖为空 | ScreenManager 统一 _resolver.Inject，禁止 FindObjectOfType |
| 本地 LLM 性能不足（低配卡顿） | 量化分层、延迟生成、轻量模型先可用 |
