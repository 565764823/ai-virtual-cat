# 🔀 Phase 1 · MVP — 合并代码与功能测试

> 由 [`../合并代码.md`](../合并代码.md) 模板复制而来。Phase 1 交付物以「Unity C# 代码 + 数据层 + 选猫/聊天/提醒/心情 UI」为主，合并前按以下清单自检，合并后按测试清单验证。

---

## 一、合并前自检清单

- [ ] Unity 工程编译通过，无致命报错（或仅剩已备案的警告）
- [ ] 本阶段核心功能已手动跑通一遍（选猫→聊天→提醒→心情记录）
- [ ] 数据层迁移器对齐 schema.sql，旧库可无损升级，二次启动幂等跳过
- [ ] 存档/表结构如有变更，已附带迁移脚本 + 回滚方案，并用旧存档实测
- [ ] 无大文件（模型/素材/NuGet DLL 误判）误提交进 Git，已按 `.gitignore` 排除
- [ ] 新增代码有注释，命名与现有脚手架风格一致
- [ ] 本阶段 [`收集问题.md`](收集问题.md) 问题状态已更新

---

## 二、合并流程（Git 分支策略）

沿用 **main（稳定）+ feature（功能）** 模型：

1. 从 `main` 创建功能分支：`phase1/feat-<任务>`（如 `phase1/feat-data`、`phase1/feat-adopt`）
2. 小步提交，提交信息遵循 `type(scope): subject`（如 `feat(data): 落地 sqlite-net-pcl 数据层`）
3. 本地跑通「功能测试清单」→ 合并回 `main`
4. 合并后打 tag：`v0.1.0-m1` 标记 M1 里程碑
