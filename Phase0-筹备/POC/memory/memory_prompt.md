# 🧠 记忆抽取 System Prompt（T0-5 交付物）

> 目标：从「猫咪与用户的对话」中抽取**对长期陪伴有复用价值**的稳定事实，结构化落库，供后续检索注入。
> 这是 Phase 2「长期记忆系统」的抽取模块 POC——只验证「能否抽出值得记的事实」，向量化/检索/注入见 `memory_poc.py`。
> 采用「本地 LLM 零样本抽取」，模型 Qwen2.5-7B-Instruct。

---

## 一、记忆结构（含归属标记）

每条记忆是一个「事实三元组 + 向量片段 + 事件时间线」的最小载体：

| 字段 | 含义 | 示例 |
|------|------|------|
| 主体 | 事实关于谁（用户 / 猫） | 用户 |
| 关系 | 主体与客体的关系（动词/短语） | 在准备 |
| 客体 | 关系指向的具体内容 | 考研 |
| 事实 | 一句可独立理解的自然语言复述（用于注入） | 用户正在准备考研 |
| 归属 | **用户级 / 猫级**（支撑多猫共存，P2 即预留） | 用户 |
| 置信度 | 0~1，明确陈述高分，推测低分 | 0.9 |

> 归属标记：`用户` = 描述用户自身的稳定属性/状态；`猫` = 描述猫（名字/品种/与用户的关系约定）。
> 抽取时顺便给「主体/关系/客体」三元组，向量化阶段由 `memory_poc.py` 对「事实」字段算向量。

---

## 二、抽取口径（要/不要）

| 要抽取 | 不抽取 |
|--------|--------|
| 用户稳定属性：名字/职业/身份/年龄/喜好/忌口/过敏/家人/宠物 | 一时情绪（"今天好累""好开心"） |
| 用户长期状态：在备考/在读/长期作息/长期在做的事 | 寒暄、单次事件（"刚吃了顿饭"） |
| 重要日程：考试/面试/纪念日/生日 | 猫当次的回复内容 |
| 猫与用户的关系：猫的名字/品种/称呼/约定 | 转瞬即逝的天气/闲聊 |

---

## 三、System Prompt（脚本从下方代码块提取）

```
你是一个「猫咪陪伴」应用的记忆抽取器。下面给你一段【猫咪与用户的对话】。请逐句检查，把对话中出现的**每一个**对「后续长期陪伴」有价值的稳定事实都抽出来作为长期记忆，宁多勿漏。

【要抽取】
- 用户属性：名字、职业、身份、年龄、所在阶段（如考研/在读/工作）
- 用户喜好与忌口：喜欢/讨厌吃什么、喝什么、过敏、口味偏好
- 用户长期状态：正在备考、在读什么、长期作息或身体情况
- 重要日程：考试、面试、纪念日、生日、约定时间
- 猫的身份：名字、品种、颜色、年龄、性别、用户对猫的称呼
- 用户与猫的关系约定：给猫起的名字、和猫的约定

【不抽取】
- 一时情绪（"今天好累""好开心"）、寒暄、单次事件、猫当次的回复内容

【每条记忆字段】
- 主体：这条事实关于谁，通常是「用户」或「猫」
- 关系：主体与客体的关系，用简短动词/短语（如：喜欢、讨厌、是、养了、在准备、下周要、面试的是）
- 客体：关系指向的具体内容（如：喝咖啡、香菜、橘猫、考研、面试、程序员）
- 事实：用一句自然语言完整复述，可独立理解，供后续注入对话
- 归属：只能取「用户」或「猫」——这条事实主要描述谁，就归谁
- 置信度：0~1。明确陈述给高分（≥0.8），推测/不确定给低分（<0.6）

【输出】只输出一行 JSON 数组，不要任何多余文字、不要 markdown 代码块。没有可抽取事实就输出 []。字段格式示例（多条各占一个对象）：
[{"主体":"用户","关系":"喜欢","客体":"喝咖啡","事实":"用户喜欢喝咖啡","归属":"用户","置信度":0.9},{"主体":"猫","关系":"是","客体":"橘猫","事实":"猫是一只橘猫","归属":"猫","置信度":0.9}]
```

## 四、采样参数（抽取用，非聊天）

| 参数 | 值 | 说明 |
|------|----|----|
| temperature | 0.1 | 抽取要求确定性，远低于聊天（0.7）|
| top_p | 0.9 | 保留 |
| repeat_penalty | 1.15 | 与聊天一致 |
| max_tokens | 600 | 一次可抽多条事实 |
