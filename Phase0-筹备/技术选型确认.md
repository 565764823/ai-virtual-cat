## 三、关键决策逐条说明

### 3.1 游戏引擎：Unity 6 LTS（🟡）
- **决策**：Unity 6 LTS（6000.x）；若 Live2D/LLMUnity 兼容性问题，兜底 2022.3 LTS。
- **理由**：2026 年 Unity 6 是当前 LTS，2D/URP/包生态成熟。
- **风险**：个别第三方包（Live2D/XCharts/LLMUnity）对 Unity 6 的支持版本差异。
- **兜底**：退回 2022.3 LTS（第三方兼容性最广）。

### 3.2 本地 LLM：LLMUnity（✅）
- **决策**：LLMUnity（llama.cpp 封装）为主，Unity Sentis（ONNX）为备选。
- **理由**：GGUF 生态成熟、流式输出/采样参数齐全、社区活跃，适合「对话+人设 Prompt」。
- **风险**：llama.cpp 原生库在 Windows 的打包/加载坑（路径、依赖 DLL）。
- **兜底**：改用 Sentis 跑 ONNX（同一模型可转 ONNX）。

### 3.3 对话模型：Qwen2.5-1.5B（🟡）
- **决策**：Qwen2.5-1.5B-Instruct Q4_K_M（约 1.1GB）起步，3B Q4 作为「大模型可选下载」。
- **理由**：中文效果好、体积适配 4GB 显存、指令跟随强（适合人设 Prompt）；符合「轻量先可用、大模型可选」。
- **风险**：1.5B 人设表现可能不够「像一只猫」。
- **兜底**：升级 3B；Prompt 强化；联网时可选切云端 Claude 增强。

### 3.4 Embedding：bge-small-zh-v1.5（✅）
- **决策**：bge-small-zh-v1.5（ONNX 或 GGUF，约 100MB）。
- **理由**：中文语义检索效果好、体积小、本地推理快。
- **兜底**：接入困难时 MVP 先退化为关键词/BM25 检索（T0-5 验证）。

### 3.5 数据库：SQLite + sqlite-net-pcl（✅）
- **决策**：SQLite 单文件库；C# 侧用 sqlite-net-pcl（轻量 ORM）；原生 sqlite3 库随 Unity 打包。
- **理由**：单机数据本地化、无服务器；sqlite-net-pcl 对 Unity 友好、API 简洁。
- **风险**：原生库在 IL2CPP/各平台下的链接问题。
- **兜底**：Microsoft.Data.Sqlite（ADO.NET）；建模阶段用 Python sqlite3 原型对齐 schema。

### 3.6 VContainer + UniTask（✅）
- **决策**：VContainer 做 DI，UniTask 做异步。
- **理由**：解耦模块（AI 引擎/存档/UI），UniTask 性能与可读性优于协程。
- **兜底**：无（标准做法）。

### 3.7 动画：Live2D Cubism（✅）
- **决策**：Live2D Cubism（2D 立绘动画）为主；兜底 Spine 2D / Rive。
- **理由**：用户已指定 Live2D；对猫咪拟人化表情/口型/动态表现力强，适合陪伴类产品。
- **风险**：Live2D 授权与 Cubism SDK for Unity 的集成/学习成本。
- **兜底**：Spine 2D / Rive（若 Live2D 接入不顺再切换）。

### 3.8 通知（✅）
- **决策**：游戏内 UI 通知（猫咪拟人化）+ 桌面 Windows Toast。
- **理由**：PRD Q5 已确认 MVP 两者都做。
- **风险**：Windows Toast 需轻量原生插件。
- **兜底**：Toast 接入难时，MVP 先用简单托盘/系统通知，游戏内通知兜底。

### 3.9 情绪识别与内容安全（✅）
- **决策**：本地 LLM 细粒度分类（5 类 + 强度 1~5，对象为**用户**）+ 词典/规则兜底；危机识别 MVP 仅敏感词过滤（PRD Q7）。
- **理由**：PRD Q2/Q7 已确认。
- **兜底**：无 LLM 时词典 + 规则为主。
